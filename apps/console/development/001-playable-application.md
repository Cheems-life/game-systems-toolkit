# 001：可交互的命令行应用层

- 日期：2026-10-25；状态：已实现并验证。
- 目标：提供不用阅读测试就能运行的统一入口，连接配置、购买、交互、对话、任务、资产及存档。

## 设计与边界

应用拥有已校验的内容包、语言表、一个Player和存档路径。共享商品表由应用传入，交互/对话目录按当前Player契约装配。不改领域规则、不绕过领取条件、不把UI选择直接写进任务进度。

场景为新手村：初始5级、500金币；购买补给；接“出发准备”；调查路标并完成向导对话；两个绑定目标达成；领奖后保存。战斗未实现，不伪造击杀。初始等级/金币/格数为这个应用的启动策略，任务与商品仍来自JSON。

命令行优于本步直接接Godot：无需引擎即可观察全部业务流程，后续可替换输入输出层。可交互入口与现有一次性示例并存；应用放apps，不把业务搬进tests。支持脚本输入仅为同一真实应用入口的端到端验证。

## 状态和失败

每次修改调用Player业务接口，错误不终止交互会话；脚本模式失败立即非零退出。请求ID由应用生成，恢复后扫描全部成功历史避免重复。只有完成对话才经Player发任务事实；未接任务前事实不补算。

启动发现指定存档时自动恢复，损坏则退出，不能悄悄新建覆盖。保存创建父目录后走save_atomic；durability_uncertain不显示可靠保存。退出不自动保存，明确未保存提示。内存成功与落盘分离，不宣称网络/并发/数据库能力。

- ASan/UBSan：build/sanitized配置address,undefined及fno-omit-frame-pointer后构建并执行全部CTest，51/51通过。
- 手动运行真实应用的walkthrough.txt，金币500→400→500、药水5→7，交互与对话两个目标完成后领取，保存成功。
- tests/application/full_flow.cmake启动独立进程验证对话在选项节点保存、重启后继续并领奖、继续新购买ID不冲突、重复领奖拒绝、交互输入错误后继续、损坏存档和非法配置不覆盖文件。
- 本地Markdown链接及git diff --check通过。未验证图形引擎、Windows保存、网络、并发或性能。领域单元测试继续由各模块维护。
