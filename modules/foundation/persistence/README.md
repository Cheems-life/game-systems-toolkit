# 存档与持久化

状态：实验性 C++17 文件适配器，当前在 macOS 验证。目标 `designer::persistence`，公开头文件 `designer/persistence/file_store.hpp`。

## 职责与分层

本模块保存与读取字节，不理解背包、物品、容器或格式版本，不依赖 inventory。背包的快照编码、数据验证和恢复位于 inventory；调用方组合两者。

- `save_atomic(path, bytes, max_bytes)`：同目录临时文件写入 → 文件 fsync → 关闭 → rename 替换 → 目录 fsync。
- `load_file(path, output, max_bytes)`：限制大小、完整读取，成功后才替换输出字符串。

默认上限 16 MiB；路径为空、文件名为空、`.`、`..` 或包含 NUL 时拒绝。父目录必须已存在，不自动创建目录。分配失败仍使用标准异常语义。

## 保存结果与失败边界

| 结果 | `committed` | 调用方应如何理解 |
| --- | --- | --- |
| `none` | true | 已替换正式文件，文件和目录同步调用成功 |
| `too_large` / `invalid_path` / `io_error` | false | 尚未替换正式文件，旧文件保留 |
| `durability_uncertain` | true | 已替换，但目录同步失败，不能声称未提交 |
| `unsupported_platform` | false | 当前没有该平台的原子保存适配 |

临时文件用 mkstemp 独占创建，默认仅当前用户可读写。普通失败会清理临时文件；进程被终止可能留下临时文件，加载只使用明确指定的正式文件，不会自动把残留临时文件当存档。新文件替换会使用新文件权限，不保留旧文件元数据。

POSIX 平台提供当前保存实现，其他平台返回 `unsupported_platform`。Windows 保存适配尚未实现；读取使用标准 C++ 文件 API。只验证了本机 macOS 本地文件系统，Linux 及其他文件系统未验证。

fsync 与原子替换提供文件系统层面的机制，不代表已完成真实断电测试或能够消除硬件、文件系统和存储设备的所有故障。当前不支持多个写入者、网络文件系统或外部同时修改文件；文件夹及路径由可信调用方控制。读取也不承担路径隔离、反符号链接或防恶意文件系统职责。

## 当前不包含

云存档、多设备冲突、数据库、自动备份找回、加密、格式迁移和跨文件事务。损坏存档的检测由领域解码器负责；没有备份时，拒绝损坏文件不等于能找回丢失的数据。

内存转移成功与文件保存成功是两个边界。如果保存失败，调用方保留当前内存状态并标记未保存，重试保存即可，不能再次执行同一笔转移。线上请求幂等性与数据库事务另行设计。

## 验证

测试覆盖初次写入、替换已有文件、二进制及空内容、读取上限、缺失路径、保存上限、目标为目录导致替换失败、失败后临时文件清理，以及多个容器的真实文件往返。示例用两个独立进程验证保存与恢复。

尚未注入磁盘写满、write/fsync 失败或目录同步失败，也未进行断电与杀进程故障演练。商业级验收见 [质量要求](../../../docs/quality.md)。
