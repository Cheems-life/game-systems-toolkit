## 场景、目标与范围

测试源码平铺已不便于按背包、经济和商城学习。将同一模块的规则、格式、异常测试和辅助头文件归入同一目录，根目录只保留总入口与导航。不改变领域实现或测试断言。

## 数据模型与规则

无新领域数据模型。采用 core、inventory、persistence、economy、commerce 五个子目录，各自维护 CMakeLists.txt。保留既有构建目标名、CTest 名称和保存/加载 fixture 依赖。经济辅助文件属于 economy，商城以显式相对路径复用它，不添加全局头文件搜索路径。

## 方案与选择理由

按功能而非测试类型分类，使一个系统的规则与异常测试集中可读。相比根 CMake 继续列出全部源码，子目录独立注册能让依赖及跨进程示例归属更明确。暂不建立通用 shared/support 框架，只有商城确实复用经济辅助。

## 实现过程与失败处理

先记录文件映射，再移动源码和辅助文件；拆分构建注册，修正跨目录 include 与当前文档链接。旧开发记录中的平铺路径保留为历史，当前路径由测试导航映射。文件测试继续使用所属构建目录下的独占临时目录，fixture 的存档路径也随模块隔离。

不涉及业务状态提交、并发或数据库事务。测试目标与 fixture 不能丢失或重名；通过全新构建目录验证，避免旧二进制掩盖遗漏。

## 验证

- 环境：macOS、AppleClang 17，Debug；使用全新 `build/test-layout` 目录。
- 命令：`cmake -S . -B build/test-layout -DCMAKE_BUILD_TYPE=Debug`、`cmake --build build/test-layout --parallel`、`ctest --test-dir build/test-layout --output-on-failure`。
- 实际结果：构建成功，全部 17 项 CTest 通过，包括三个跨进程保存/加载 fixture。
- 静态核对：13 个 C++ 文件完整迁移，除商城辅助中的跨模块 include 外与原文件内容一致；本地 Markdown 链接及 `git diff --check` 通过。
- 本次未重新运行内存检查，未新增业务规则测试。
- 未覆盖：其他平台及新的性能、并发或故障测试；本步没有新增测试用例。
