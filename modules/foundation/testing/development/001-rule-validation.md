## 场景与问题

验证可编译只是起点，需要用规则、状态模型和故障路径检验设计。

## 数据、接口与关键规则

CTest 注册独立测试程序，显式条件检查在 Release 下也生效；关键系统采用确定性连续操作、格式变异、分配失败注入及独立进程恢复。

## 为什么这样设计与替代方案

仅复述实现或依赖 assert 的测试可能遗漏真实错误或在 Release 中失效。固定随机种子便于复现；独立数量模型比只观察返回码更能检验守恒。暂不引入外部测试框架以保持最小依赖。

## 实现步骤与提交边界

基础链接冒烟 → 规则边界 → 连续操作 → 文件格式/文件 I/O → 分配异常 → 跨进程保存恢复。具体测试归各领域模块，本模块当前是质量入口，不是独立测试框架库。
