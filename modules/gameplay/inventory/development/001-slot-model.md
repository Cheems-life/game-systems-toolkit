## 场景与问题

定义背包究竟保存什么，避免空格、零数量和无效物品等矛盾状态。

## 数据、接口与关键规则

ItemDefinition 保存 ID 和单格上限；ItemStack 保存 ID 和实际数量；Slot 使用 optional；Inventory 拥有固定槽位和自有不可变规则。

## 为什么这样设计与替代方案

定义与持有状态分离，避免在每格重复配置。用 optional 表达空格比用特殊 ID/零数量更明确。规则副本易理解且无外部生命周期风险，但有重复内存成本；共享规则暂留待性能证据驱动。

## 实现步骤与提交边界

先写正数 ID/上限及非空堆数量范围 → 构造时拒绝重复或非法规则 → 提供只读槽位访问 → 再定义修改接口。
