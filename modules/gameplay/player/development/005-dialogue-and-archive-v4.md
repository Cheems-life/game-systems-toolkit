# 005：对话完成事实与玩家格式 v4

## 场景、目标与范围

Player 组合对话，不让对话底层依赖任务或完整玩家。结束会话、成功回执和任务事实必须一起提交；任务拒绝时会话停留在原结束节点，可原请求重试。

## 数据模型与规则

State 增加 dialogue::Book，当前 Catalog 独立保存。execute_dialogue_command 处理统一命令；完成时按既有 QuestBook.event_cursor()+1 生成 type=冻结完成类型、subject=对话 ID、quantity=1 的事实，检查溢出。非完成和取消不生成事实。对话请求 ID 与经济/交互请求 ID 分域。

PlayerSnapshot 增加对话快照。DQSTARCH 写 v4、读 v1..v4，在 v3 交互列表后追加有界独立 DDLGARCH v1 字节段（u32 长度+字节），旧版本补空对话状态。恢复校验每条完成凭证与原始任务事实相等，且不能与交互抢占同一事实序号。

## 方案与选择理由

独立对话编解码可用于无 Player 的游戏；嵌入同一玩家文件避免分文件提交错位。只在确认完成时产生业务事实，UI 显示/点击不是世界副作用。与 NPC 交互的打开动作由应用层明确调用，不隐式合并为一个事务。

## 实现过程与失败处理

旧回执优先重放；新命令在候选处理。完成后投递任务事实，再准备返回对象并交换。任务失败、容量或分配失败均丢弃候选。所有既有购买/领奖/交互复制路径保留对话状态。存档编解码保持输出在失败时不变。
