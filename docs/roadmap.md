# 实施路线

已确定：设计学习优先，类 MMO 参考场景，C++17/CMake 核心库，Godot 后续适配。工程基础已建立，背包、跨容器转移、本地存档、第一版经济事务及游戏内商城已实现并通过规则测试。

## 实施顺序

1. 背包与物品：数据建模、堆叠、容量、添加/移除/移动，验证数量守恒和失败原子性。
2. 存档：保存与加载、数据版本、迁移和损坏恢复。
3. 货币与奖励：资产变更、事务边界和重复请求。
4. 属性、装备、技能、战斗：组合、计算顺序和效果生命周期。
5. 任务、对话、AI：状态机、条件与事件协作。
6. 邮件、抽卡、商店、活动：复用资产与奖励能力。
7. 联网与服务端适配：验证可信端、并发和断线恢复；其他模块按实际场景引入。

每一步先写场景、规则和数据，再写最小实现与验证。MMO 权威边界从设计阶段考虑，联网工程不作为学习第一步的前置条件。

## 当前完成与下一步

第一版采用固定格数和同类堆叠，已实现添加、移除、移动和交换，完整规则见背包 README。已完成快照/本地存档、宝箱全部拾取和仓库双向转移。经济模块已增加钱包、奖励、购买、成功请求去重和统一经济存档；唯一装备实例和线上并发/持久化确认仍待设计。

游戏内商城已验证商品计价、改价后重放及统一存档。任务已验证一次性业务状态与资产协同。任务/邮件的一次性领取状态必须与发奖一起提交，不能把请求去重当业务领奖限制。经济聚合内部的跨容器转移命令、长期去重记录保留、配置迁移仍需后续设计。

目标平台、参考游戏具体玩法、并发规模、正式数据迁移策略、服务端技术与部署、Godot 适配方式、发布许可证。后续依赖按实际功能选择，并记录版本、授权和使用边界。

## 任务第一版需求修订（2026-10-18）

开启条件改为最低等级，由可信玩家上下文提供当前等级；前置任务条件延后。预留目标类型处理器注册及独立组合判定边界；当前只计划累计计数、永久达成标记和全部达成。条件求值输出布尔、稳定原因及错误；领奖使用可扩展的候选准备阶段，最终统一提交。当前仅设计文档，详见 [任务需求](../modules/gameplay/quests/README.md) 与 [决策记录](../modules/gameplay/quests/development/001-requirements-and-extension-boundaries.md)。

## 任务第一版实现（2026-10-18）

已实现通用数字计数/标记处理器注册、等级门槛、冻结多目标、严格事件序号去重、一次性领奖，以及商城/任务共享的 Player 状态。新任务格式嵌入旧商城经济快照并统一恢复；旧设计段落保留其时间背景，当前能力以 [任务 README](../modules/gameplay/quests/README.md) 为准。后续优先验证更具体的玩法适配，再决定可回退目标、更多条件或任务组合；不因接口预留就声称已支持这些能力。

玩家协调层现已独立为 gameplay/player；后续业务先实现自身规则，再评估是否纳入统一玩家事务，不反向依赖完整 Player。

## 配置加载第一版（2026-10-21）

新增单文件 JSON 包，驱动物品、货币、商品和任务目录。严格检查结构、范围、目标处理器与跨表引用，全部成功后才交付配置包；已提供校验工具与配置驱动购买/领奖示例。暂不做在线热更、Excel 导表和事件绑定。玩法事实到任务目标的绑定已在下一步实现，后续按真实场景扩充条件/目标，见 [配置模块](../modules/foundation/configuration/README.md)。

## 任务事实绑定第一版（2026-10-21）

已接入精确类型/对象匹配及 quantity/one 输入映射，冻结绑定、原始事实去重、领奖后排除和完整恢复重建。配置可读 v1/v2，玩家存档写 v2/读 v1/v2。下一步可选择一个实际玩法（如交互或对话）作为可信事实源，先定义事实何时算成功，以及资产变更和任务投递失败时如何协调，再决定是否增加条件/组合规则。

## 世界交互第一版（2026-10-22）

已实现每玩家一次/重复检查、成功请求重放、与任务事实联合提交、JSON v3 表以及玩家存档 v3（读旧版本）。失败不消耗一次性交互。当前只做无物品检查，距离/权限/视线交由可信引擎或服务端接入层；下一步再根据具体场景选择对话源、交互奖励或条件扩展，不把原型宣称为完整多人世界系统。
