# 实施路线与技术栈讨论

## 建议实施顺序

1. 确定第一个参考游戏、首发平台、引擎和语言，建立最小构建与测试环境。
2. 实现运行时、配置、诊断及一个完整的持久化场景；其他基础模块按需求引入。
3. 以“获得物品 → 放入背包 → 使用或消耗 → 保存 → 重启恢复”为第一条端到端示例，验证事务与迁移。
4. 加入任务、对话或 AI 中最符合参考游戏的一个模块，检验接口能否复用。
5. 用第二种游戏或不同规模的场景验证通用性，再稳定公共 API。
6. 需要在线服务时，再确定客户端与后端边界，实现账号、邮件或在线经济。

每一步交付可运行示例和验证结果，不同时铺开全部模块。

## 需要共同决定的事项

- 首个参考游戏：2D/3D、实时/回合、单机/联网、预期规模。
- 引擎与语言：优先服务首个实际项目；再评估独立核心与多引擎适配的成本。
- 平台：桌面、移动、Web、主机中的首发与后续目标。
- 交付形式：引擎插件、语言包、示例工程，或组合方式。
- 数据工作流：配置来源、策划编辑器、存档格式、迁移和内容打包。
- 在线范围：是否自行提供服务端实现、部署及运营工具。
- 发布方式：内部工具还是开源产品；许可证、版本策略和兼容承诺。

当前不预选引擎、框架、数据库或云服务，也不把多引擎支持作为第一版必须完成的目标。
